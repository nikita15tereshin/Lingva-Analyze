## 2. Найденные дефекты (критично)

1. src/api/main.py НЕ ИМПОРТИРУЕТСЯ: импортирует несуществующую get_index_from_db (в crud.py она называется get_document_index_from_db) и вызывает save_nlp_data_to_db(db, doc.id, nlp_data, index_data) с 4 аргументами при сигнатуре на 3. API-сервис полностью нерабочий.
2. test_llm.py импортирует analyze_semantic_context, которой нет (есть только *_stream). Тест падает.
3. test_parser.py импортирует PDFReader, которого нет в reader.py. Тест падает.
4. Миграция Alembic отстала от моделей: в БД нет таблицы regional_dictionary (seed_dictionary.py создает ее через create_all, мимо alembic), нет индексов на sentences.document_id и lexical_index.(token_id, sentence_id).
5. Дублирование логики индексации: indexer.build_index считает позицию с учетом пунктуации, а crud.save_nlp_data_to_db пропускает PUNCT, но сохраняет исходный enumerate-позиции; position в разных местах считается по-разному. build_index нигде в проде не нужен (индекс можно восстановить из lexical_index).
6. Token.lemma UNIQUE глобально, но POS не сохраняется: глагол "bestehen" и существительное "das Bestehen" сливаются в одну лемму. Для P2 (пассив "wird ...") и P9 (-in суффиксы) нужна часть речи.
7. Sentence.text собирается склейкой токенов (" ".join(word)); пунктуация сохраняется, но при нормализации теряются переносы строк таблиц и заголовков PDF. Таблицы из PDF (пункт 5.2.1 Б) не обрабатываются вообще.
8. Частотность LexicalIndex.frequency определена, но всегда NULL/1 — реальная статистика (пункт 4.1) не пишется.
9. tasks_db в API — словарь в памяти процесса: статусы теряются при рестарте и не видны при нескольких воркерах.
10. Хардкод LLM-ключа в llm.py (sk-yqac...) — ключ уже засветрован в git, его нужно отозвать и перевыпустить.
11. get_contexts_for_lemma делает N+1 запросов (по запросу на каждое вхождение) и возвращает ВСЕ контексты, UI берет только contexts[0].
12. compare.py print_comparison_table печатает битую markdown-таблицу (не используется UI, мертвый код).
13. .env.example отсутствует; docker-compose требует POSTGRES_PASSWORD, alembic.ini требует {DB_PASSWORD} — два разных механизма подстановки пароля, ни один не документирован.

## 5. Архитектурные советы

- Схема "UI обращается к БД напрямую" — временная; целевая схема: Parser -> NLP -> Indexer -> PostgreSQL <- QueryEngine(FastAPI) <- Streamlit. Единственный владелец бизнес-логики — API.
- Индекс в памяти session_state дублирует БД и живет только до перезапуска; источник истины — lexical_index в Postgres, UI должен читать оттуда по document_id.
- Статусы фоновых задач — в таблицу tasks в БД (или Redis), не в dict процесса.
- Морфология: de_core_news_sm слабовата на составных существительных и именах; для корпуса гос. отчетов заложить de_core_news_lg (или трансформерную модель) как опцию; lemma+POS+word форму хранить всегда.
- Версионирование корпусов: поле corpus_version/загрузка партиями, чтобы повторные прогоны анализа были воспроизводимы (важно для диссертации).
- Тесты: pytest вместо ad-hoc test_*.py в корне; фикстура с SQLite/Postgres-контейнером; сквозной тест "Marille находится только в AT-документе".
- Конфигурация: pydantic-settings, единый .env (DATABASE_URL, LLM_API_KEY, LLM_BASE_URL, LLM_MODEL), .env.example в репозитории.
