# Lingva-Analyze

Lingva-Analyze — сервис сравнительного анализа региональных вариантов немецкого языка (Германия, Австрия, Швейцария) на материале официально-деловых документов и устных выступлений. Проект автоматизирует полный цикл исследования: извлечение текста, морфологическую индексацию, поиск различий по матрице параметров (P1-P9), систематизацию результатов и подготовку данных для качественного анализа.

## Основные возможности

**Загрузка и парсинг.** Извлечение текста из `.txt`, `.pdf`, `.docx`. Для PDF используется PyMuPDF: текст извлекается по блокам, таблицы распознаются через `find_tables()` и сохраняются как структурированные данные.

**Морфологическая индексация.** Токенизация и лемматизация через spaCy (`de_core_news_sm`). Поиск идёт по леммам, поэтому словоформы находятся по начальной форме: `musste`, `gemusst` попадают в выдачу по запросу `müssen`. Каждое вхождение сохраняется с координатами (документ, предложение, позиция).

**Матрица параметров (P1-P9).** Параметр описывается данными в БД, а не кодом, — новые критерии добавляются без изменения движка. Поддерживаемые типы запросов: набор лемм, два слова в одном предложении (KWIC-комбинация), регулярное выражение по словоформе, лексическая пара/тройка для замен одного концепта по странам, матчинг по региональному словарю, частотный диапазон. Пресеты: P1 нормативность, P2 пассив, P3 модальность, P4 интертекстуальность (ссылки на НПА, §, Art.), P5/P6 австрицизмы и гельветизмы, P8 лексические замены, P9 гендерные формы (-in), STAT-YEARS (частота цифр с отдельной подсветкой годов), FREQ-1-5 (слова с частотой до 5 раз).

**P7 семантические сдвиги (гибридный дисамбигуатор).** Для слов, значащих разное в разных странах (например, `Gymnasium`), действует трёхуровневая схема: сначала collocation-правила разрешают однозначные случаи, затем векторная близость (эмбеддинги spaCy) сравнивает контекст с эталонными примерами значений, и только остаток спорных попаданий одним пакетным запросом уходит в LLM. Основной объём размечается кодом, токены экономятся; каждое решение помечено уровнем уверенности (rule / vector / llm).

**Региональные словари.** Модуль `src/dictionaries/` парсит 15 глоссариев DE/AT/CH (спецслужбы, полиция, юстиция, безопасность) через HTTP, headless-браузер (Camoufox/Playwright для JS-сайтов вроде termdat) и PDF-загрузки. Данные попадают в staging-таблицу с валидацией (для австрийского полицейского глоссария — отсев германизмов); подтверждение записей — вручную из UI или эндпоинтом approve. Обновление всех источников — одной кнопкой «Обновить словари».

**Количественный и качественный вывод.** По каждому параметру: сводная pivot-таблица (страна x документ x число попаданий) и список хитов с полным предложением и подсветкой найденного слова. Экспорт: CSV по параметру, общий CSV и XLSX-книга (лист статистики + лист всех вхождений) для дальнейшей работы.

**LLM-слой.** Качественный разбор (структура документа, тональность, угрозы, метафоры) и дисамбигуация P7. Провайдер и ключ настраиваются на отдельной вкладке UI: выбор из списка (TokenRouter, OpenAI, Anthropic, DeepSeek, Groq, OpenRouter, локальная Ollama, Custom), ввод ключа со скрытием символов. Ключ хранится на сервере, во фронтенд возвращается только маска.

## Технологический стек

* **Backend:** FastAPI, Python 3.11+, Streamlit (админ-панель).
* **База данных:** PostgreSQL, SQLAlchemy, Alembic (миграции).
* **NLP/ML:** spaCy, эмбеддинги для векторной дисамбигуации, OpenAI-совместимый API.
* **Парсинг:** PyMuPDF, python-docx, BeautifulSoup, Playwright/Camoufox.
* **Экспорт:** pandas, XlsxWriter.

## Структура проекта

```
src/api/           FastAPI-сервер (загрузка, индексация, параметры, экспорт, словари, LLM-настройки)
src/ui/            Streamlit-интерфейс (Лексика, KWIC, Матрица, Словари, LLM)
src/nlp/           Обработка текста spaCy, построение индекса
src/parser/        Извлечение текста и таблиц из txt/pdf/docx
src/db/            Модели, CRUD, миграции Alembic, сид словарей
src/query/         Движок матрицы параметров, пресеты, экспорт CSV/XLSX
src/analysis/      Сравнение индексов, контексты, гибридный дисамбигуатор P7, настройки LLM
src/dictionaries/  Парсеры глоссариев DE/AT/CH, синхронизация, валидация
tests/             pytest-набор (движок, API, парсеры, словари, семантика)
```

## Установка и запуск

**1. Зависимости и модель spaCy**

```bash
pip install -r requirements.txt
python -m spacy download de_core_news_sm
```

**2. Переменные окружения (.env)**

```
DATABASE_URL=postgresql://user:password@localhost:5432/lingva
LLM_API_KEY=            # опционально: можно задать позже через вкладку LLM
LLM_PROVIDER=           # опционально: провайдер по умолчанию
```

Ключи LLM в коде не хранятся; при пустом значении эндпоинты LLM возвращают понятную ошибку вместо падения.

**3. База данных и миграции**

```bash
docker-compose up -d          # PostgreSQL
alembic upgrade head          # схема, включая semantic_shifts и словари
```

**4. Инициальные данные**

```bash
python src/db/seed_dictionary.py   # стартовые австрицизмы/гельветизмы
curl -X POST http://localhost:8000/parameters/seed   # пресеты P1-P9, STAT-YEARS, FREQ-1-5
```

**5. Запуск компонентов**

* **API:** `uvicorn src.api.main:app --reload`
* **UI:** `streamlit run src/ui/app.py`

## Типовой рабочий процесс

1. На вкладке «Лексика» загрузить документы, указать страну (DE/AT/CH) и тип корпуса, запустить индексацию.
2. На вкладке «Матрица» выбрать параметр и получить сводку по странам и список вхождений с подсвеченным контекстом.
3. Для P7 заполнить справочник слов-омонимов (слово, страна, значение, эталоны контекстов) и запустить дисамбигуацию: код разметит большинство случаев, спорные уйдут в LLM.
4. На вкладке «Словари» нажать «Обновить словари», выбрать источники, подтвердить новые записи после валидации.
5. Выгрузить workbook.xlsx и передать результаты этапу сравнительного анализа.

## Статус и известные ограничения

* Пункт 4.3 ТЗ (собственно сравнительный анализ) выполняется автором вне системы на основе экспортированных данных.
* Список слов для P7 и часть пар для P8 заполняются вручную по мере пополнения матрицы параметров.
* Селекторы парсеров словарей могут требовать подстройки под вёрстку сайтов; ошибки конкретного источника видны в таблице статуса обновления.
* UI обращается к слоям БД и NLP напрямую, минуя REST API; вынос тяжёлых операций в фоновые задачи — план ближайших доработок.
